## 2. What runs today

A QRE in either format becomes a validated, provenance-bearing extraction:

```
QRE (.docx / .pdf) → NormalizedDocument → QREExtractionIR → JSON
```

Across the 15-document development corpus:

| | Documents | Questions | Unparsed retained | Review items |
|---|---|---|---|---|
| DOCX | 13 | 238 | 365 | 242 |
| PDF | 2 | 112 | 723 | 112 |
| **Total** | **15** | **350** | **1,088** (276 flagged) | **354** |

Also extracted: 472 instructions, shallow-classified as routing, display,
validation, quota, randomization, piping or disposition, with the raw text
preserved verbatim.

Properties enforced by tests rather than by intention:

- **Content conservation.** Every ingested block and table is represented in the
  IR, if only as retained unparsed content. Nothing is silently dropped.
- **Verbatim instructions.** Instruction text is byte-identical to source.
- **No invented codes.** A response label without a code yields `null`.
- **Determinism.** Identical input produces byte-identical output.
- **Vocabulary independence.** Column roles are discovered through a
  configurable synonym table, not hard-coded. Proven with a German-header test:
  unknown headers yield zero questions plus a review flag, and the same table
  extracts once its synonyms are configured.

## 3. What is NOT established

Stated plainly, because these are easy to assume from a green test suite:

- **Extraction accuracy is unknown.** Not high, not low — unmeasured. The 350
  questions have never been compared against what a human says the QREs ask.
- **The 116 passing tests measure consistency, not correctness.** They were
  written from the same reading of the documents that produced the reader. A
  shared misreading passes every one of them.
- **PDF extraction quality is unverified**, and structurally more suspect than
  DOCX: PDF questions come from prose, DOCX questions from tables with headers.
- **Generalization to real Escalent QREs is unproven.** All 18 fixtures are
  synthetic and were authored together. The reader may have learned their shared
  house style rather than survey documents in general.
- **The review queue has never been used by a reviewer**, so we do not know
  whether 354 items across 15 documents is workable or unusable.

## 4. Blockers

**B1 — Nobody has been assigned to code ground truth.** Fifteen blank worksheets
are ready. Until they are filled, Stage 8 cannot run and no accuracy claim about
this project is defensible.

**B2 — The ground-truth authorship question is open** (decision 0003). The
reader was written by Claude Code from these documents; if Claude Code also
writes the expected answers, both carry the same misreadings and the evaluation
measures agreement with itself. Recommendation on record: fully human-coded for
one document per complexity tier, human-coded with difference-flagging for the
rest. **This is a team decision and it gates the value of everything in Stage 8.**

**B3 — No real or sanitized Escalent QRE has been received.** This is the
largest unknown in the project and it is external to the team.

## 5. Risks

Ordered by consequence. Severity reflects impact if unaddressed, not likelihood.

| # | Risk | Severity | Status |
|---|---|---|---|
| R1 | Accuracy unmeasured; a confident-looking extraction may be wrong | High | Open, blocked on B1/B2 |
| R2 | Reader overfitted to the synthetic corpus | High | Partly mitigated: config-driven vocabulary, 3-document holdout, unmeasured until Stage 8 |
| R3 | PDF precision unknown — 112 questions against 723 unparsed blocks | Medium-High | Open; harness reports formats separately so it cannot hide |
| R4 | Review queue may exceed the ~10-minute budget in Section 22 | Medium | Open; unparsed is flagged selectively, but never tested with a human |
| R5 | Stage 6 validation not built — duplicate IDs and malformed objects are undetected | Medium | Open; required by the Section 45 definition of done |
| R6 | `QREExtractionIR` unfrozen, so downstream work cannot rely on it | Medium | Intentional; freeze should follow ground truth, not precede it |
| R7 | Holdout depends partly on human discipline | Medium | Four technical controls; a person can still open the file in Word |
| R8 | Team unaware of new working rules (holdout, corpus API, venv setup) | Medium | Open — needs a message to the team, not code |
| R9 | LimeSurvey environment not stood up | Low now, blocking later | Deferred until Agent 2 |
| R10 | Repository name misspells the client ("Escalant" / Escalent) | Low | Open; cheap to fix before external sharing |

**On R1 and R2 together:** these are the same failure in two forms, and it is the
one CLAUDE.md Section 40 calls the highest risk in the project — an extraction
that is wrong, confident, and agreed with by everything downstream. Every
technical control built so far (provenance, conservation, the holdout, evidence
attached to confidence) exists to make that failure visible. None of them can
detect it without ground truth.

## 8. One honest note on effort

The work so far is scaffolding, tooling and one reader — roughly 3,000 lines
including tests. It was fast because it is all deterministic code written
against documents that were already available. The remaining work that
determines whether this project succeeds is not code: it is people reading
questionnaires and writing down what they say. That step has no shortcut that
does not also destroy the measurement.
